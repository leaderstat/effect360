# Seeds — фикстуры для demo-датасета

## `business_trip_fixture.json`

**Назначение:** подготовка demo-fixture типа заявки «Служебная командировка» для v0.1. На дату 2026-10-22 fixture **НЕ готова к использованию** — действующий нормативный акт известен, но дословные цитаты не внесены.

**Текущий акт (заменён 2026-10-22):** Постановление Правительства Российской Федерации от 16 апреля 2025 г. № 501 «Об особенностях направления работников в служебные командировки».

**Заменяемый акт:** Постановление Правительства Российской Федерации от 13 октября 2008 г. № 749 — утратило силу с 1 сентября 2025 г.

**Почему заменили:** `docs/tz/Check-point.md` §3 явно требует замены: «В архиве используется постановление №749 о командировках, утратившее силу с 1 сентября 2025 года. Применяется постановление №501.»

**Источник публикации (ПП № 501):** Официальный интернет-портал правовой информации (pravo.gov.ru), опубликовано 16.04.2025, номер опубликования 0001202504160034. Собрание законодательства Российской Федерации, 2025, № 17, ст. 1195. Российская газета, 2025, 25 апреля, № 91.

**Источник текста (для будущей сверки):** https://legalacts.ru/doc/postanovlenie-pravitelstva-rf-ot-16042025-n-501/ (дословный текст должен быть подтверждён пользователем или ответственным — Гульнара по распределению ролей из Check-point.md §5).

### Что нужно сделать, чтобы fixture стала готова

1. **Свериться с первоисточником.** Получить доступ к полному тексту ПП № 501 (16.04.2025) на pravo.gov.ru / Собрание законодательства РФ / в legalacts.ru.
2. **Заполнить `clauses[]` дословно** — пункты, обосновывающие каждое требование (по аналогии с тем, как было в предыдущей версии для № 749).
3. **Заполнить `requirements[].quote`** дословными цитатами из соответствующих пунктов.
4. **Прогнать citation validation:**
   ```powershell
   python .\scripts\verify_fixture_citations.py
   ```
   Скрипт ещё не создан — это §12.1 слот «22 окт». Должен читать JSON и для каждого `requirements[].quote` проверять наличие дословно в `clauses[].text` после нормализации пробелов.
5. **Поставить `request_type.enabled: true` и `regulation.status: approved`** только после успешной citation validation.
6. **Сравнить смысл связей** (Check-point.md §3): «Наличие дословной цитаты ещё не доказывает обязательность поля. В архивном наборе город связан с цитатой о денежном авансе; документы после возвращения нельзя автоматически требовать до поездки. Для каждого правила нужно подтвердить смысл связи, обязательность, условие и этап процесса.» Это значит: даже после citation validation нужно явно отметить, что требование `actual_stay_docs` (привязанное к `condition: {after_return: true}`) корректно и не нарушает процесс.

### Распределение ответственности (по Check-point.md §5)

- **Гульнара** — ИИ и бизнес-правила. Владелец fixture. Сверяет требования, получает действующее положение, заполняет clauses и quotes.
- **Дмитрий** — технический лидер. Реализует `verify_fixture_citations.py`, проверяет SQL seed (после citation validation).
- **Анастасия** — CustDev. Проверяет прототип на пользователях, валидирует обязательность полей на реальных кейсах (см. `CustDev.md` §2 — «Уточнения для командировки»).

### Что НЕ сделано (требует отдельного шага)

- Загрузка в PostgreSQL через SQL seed (`database/seeds/002_seed_business_trip.sql`) — следующий шаг ПОСЛЕ citation validation. **Сейчас делать нельзя**: `request_type.enabled=false` означает, что seed не должен вставлять активный тип заявки.
- Включение fixture в `compose.yaml` как init-script.
- Связь с основной Python/FastAPI-версией проекта (Check-point.md §1 указывает, что **Python-версия является основной конкурсной**, а Gleam-каркас в этом репозитории — экспериментальный дополнительный вариант для проверки устойчивости фоновой обработки). SQL seed нужно согласовывать с обеими версиями, иначе схема разойдётся.

### Важно

- Это **публичный** нормативный акт, не внутреннее положение организации. Использование в демо соответствует решению пользователя (Backlog.md §3.4).
- Перед production-деплоем внутреннее положение организации должно быть загружено как `approved` regulation с цитатами, прошедшими ту же верификацию (Check-point.md §3: «Для пилота предпочтительно подключить действующее внутреннее положение выбранного подразделения»).
- Никакие цитаты из ПП № 749 **не должны** оставаться в коде, документации или базе — акт утратил силу (Check-point.md §3).
