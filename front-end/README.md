# web-demo · Эффективность 360

> **Статус:** демонстрационный Nuxt UI контур. Не подключён к backend. Все данные — синтетические.
>
> **Назначение:** показать визуальную и UX-логику продукта на Nuxt UI v3 + Nuxt 4, перенеся дизайн-токены существующей Lustre-реализации (`services/frontend/styles/`). Цель — дать комиссии и заказчикам кликабельный прототип для презентации, не выдавая мок-данные за реальные.

## Что внутри

- **Nuxt 4** в режиме `ssr` (по умолчанию), `nitro.preset = 'node-server'` локально, `'vercel'` для деплоя.
- **Nuxt UI v3** как библиотека компонентов.
- **Дизайн-токены Lustre** перенесены в `assets/scss/_tokens.scss` + `app.config.ts` (маппинг на палитру `teal`/`slate`).
- **Слой мок-данных** в `composables/useMockData.ts`: заявки, очередь модерации, метрики, причины возвратов, уведомления, журнал событий, настройки режима.
- **12 страниц** по основным пользовательским сценариям (см. ниже).

## Экраны

| URL | Назначение | Соответствие Lustre |
|---|---|---|
| `/` | Главный рабочий кабинет заявителя | S0 + дашборд-виджет |
| `/requests/new` | Описание новой заявки, извлечение полей | S1 + S2 |
| `/requests` | Список моих заявок с фильтрами | P7.1 |
| `/requests/:id` | Карточка заявки, таймлайн, цитаты | P7.3 + P7.4 |
| `/notifications` | Лента уведомлений | P7.2 + P8.6 |
| `/moderation` | Очередь модератора | P7.5 |
| `/moderation/:id` | Карточка обработки исполнителем | P7.6 |
| `/metrics` | Метрики руководителя + причины возвратов | P7.7 |
| `/journal` | Журнал событий автоматизации | P8.4 |
| `/automation` | Панель автоматизации | P8.1 |
| `/settings` | Настройки режима | P8.5 |

Дополнительные экраны (P7.6 редактор ответа, P8.2 проверки агента, P8.3 исключения) можно добавлять по той же модели.

## Команды

```bash
# Установка зависимостей
npm install

# Локальный запуск (http://localhost:3000)
npm run dev

# Сборка production-бандла
npm run build

# Проверка TypeScript
npm run typecheck
```

## Деплой на Vercel

1. Подключите репозиторий к Vercel.
2. В качестве Root Directory укажите `services/web-demo`.
3. Framework Preset: `Nuxt.js`.
4. Build Command: `npm run build` (Nuxt CLI сам определяет пресет `vercel` через `nitro.preset`).
5. Output Directory: остаётся по умолчанию.

`vercel.json` уже настроен на сборку Nuxt через Vercel-preset.

**Без backend**: демо полностью автономно. Никаких секретов и переменных окружения не требуется. Не подключайте платные сервисы и не публикуйте репозиторий до проверки.

## Что нельзя делать с этим контуром

- Подключать к реальному backend или БД. Демо работает только в режиме моков.
- Использовать мок-данные в коммерческих материалах. Все имена, идентификаторы и тексты синтетические.
- Воспринимать цифры на странице «Метрики» как измерения. Они помечены «Эвристика, не измерено».
- Привязывать auth-flow к реальным учётным записям.

```

├── public/

```

## Что проверить перед показом комиссии

1. `npm run dev` → открыть http://localhost:3000 и пройтись по всем страницам.
2. Сверить визуально с Lustre-реализацией: палитра, отступы, поведение сайдбара/header.
3. Подтвердить, что на каждой странице виден баннер «Демо-режим».
4. Не делать скриншоты для коммерческих материалов без явной пометки «демо».
