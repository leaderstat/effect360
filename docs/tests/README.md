## Порядок проверки проекта другим разработчиком

1. Установить Docker Desktop 24+ с WSL2 backend и Git for Windows.
2. Склонировать репозиторий в `C:\home\Agents\effectivnost-360`.
3. Убедиться, что `.env` существует (создаётся автоматически при первом `up`; см. [`05-regression-checklist.md`](05-regression-checklist.md) § 0).
4. Из корня репозитория: `.\scripts\up.ps1` — поднимает стек.
5. Подождать ~30 секунд; проверить `docker compose ps` — все сервисы `Up`/`healthy`.
6. Прогнать `.\scripts\smoke_checks.ps1` — он выполняет 5 read-only проверок.
7. При желании — отдельные проверки по [`05-regression-checklist.md`](05-regression-checklist.md) § 10.
8. Остановить стек `.\scripts\down.ps1` (без `-Clean`, чтобы сохранить volumes).

## Известные ограничения (кратко)

- **Gleam CLI не установлен на хосте.** Полный прогон `gleam test` возможен только через `make test-gleam` внутри Docker-контейнера (требует пересборки builder-образа).
- **Playwright не установлен на хосте.** Скрипт `scripts/check-login-ui.cjs` и `scripts/qa_e2e.mjs` ожидают Playwright в `C:/tmp/shots-runner/node_modules/playwright` или в tooling-контейнере.
- **Реальная LLM недоступна.** `LOCAL_LLM_BASE_URL=http://host.docker.internal:11434` не отвечает; consumer использует heuristic fallback (это документированное поведение).
- **Production-fixture (ПП № 501) без цитат.** Цитаты заменены на TODO-плейсхолдеры (Backlog §12.1); текст акта в этой среде недоступен.
- **Backlog.md повреждён по кодировке.** Текст в нём читается как «mojibake» (кириллица → latin1). Это известная проблема, описанная в Backlog §CURRENT STEP «Восстановление файла: 2026-10-21». Содержательный смысл восстановлен, но символы местами нечитаемы. Влияет только на читаемость, не на работу кода.
